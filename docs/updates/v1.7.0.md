# v1.7.0 — Dynamic exam types, units and monthly calendar

Based on the supplied project-reference-09-10-2026-11-38-PM.zip (v1.6.3). Footer version: v1.7.0. Root README remains unchanged.

## Changes

- Exam Management adds Administrator-only Exam Types and Units CRUD. Live forms, filters, text search, reports and API options inherit these database catalogs.
- Existing five types are followed by Aptitude Test, Practical Test and Typing Test. Existing exam/staff units retain their codes and usage; administrators can add more and choose their exam/user availability.
- Rename changes visible names everywhere without rewriting schedule/user references or versions. Used entries cannot be deleted, including references from soft-deleted records. Used Viva/Unit scope settings are protected. Names/order remain editable; concurrent stale edits/deletes return 409. Metadata changes use existing actor/time/IP audit logging.
- Calendar: month navigation/picker, per-day total/type counts on hover or keyboard focus, and click/tap to open the day's details in the same table as Dashboard. Unit/type filters, shared pagination/actions and day exports are included. Bengali/English display and Asia/Dhaka month boundaries are retained. `/api/v1/calendar` supports future native clients.
- Viva behavior comes from catalog settings, including for newly added types. API codes remain immutable; clients display current names from `/options` maps. See ../API.md for metadata CRUD and calendar contracts.

## Apply

Back up the database and project. Replace the included files at the project root. Preserve .env, APP_KEY and the database.

```bash
php artisan optimize:clear
php artisan migrate
php artisan db:seed
php artisan test
```

Hard refresh with Ctrl+F5. Compiled CSS/JavaScript is included; no npm build or Composer install is required.

The migration automatically populates existing defaults and imports historical codes; it does not rewrite schedules/users. db:seed is repeatable and does not reset renamed entries or settings. If a missing seed name has been reused by another catalog entry, seeding preserves that entry and prints an English notice instead of creating a duplicate. To seed only the two catalogs later:

```bash
php artisan db:seed --class=ExamTypeSeeder
php artisan db:seed --class=UnitSeeder
```

Use Exam Management → Exam Types / Units / Calendar. Only unused entries can be deleted. All active roles can read the calendar; only existing schedule permissions permit edits/deletes from its day table.

Catalog rollback is deliberately blocked because reverting the schema alone would lose custom types/units. Restore the matching code/database backup to revert. Never use migrate:fresh on a live database.
